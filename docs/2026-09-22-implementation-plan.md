# M 键采集与炮口标尺实施计划

## 调查依据

- 当前工作树干净；基线测试 218 Core + 32 OCR 通过。AGENTS.md 的测试数量和部分 OCR 说明已落后于代码，实际 Auto 为 C × 两种 Tesseract 分页模式。
- 2026-09-22 的 Samples 共 132 帧，123 帧光标为 (960,540)。原图同时包含清晰坐标、炮位说明浮层、已关闭的地图和开图过渡读数，不能把它们统称为 OCR 阈值失败。
- 旧链路先截图整屏、PNG 编码、写盘，再另截 ROI。两次截图不是同一时刻；首张样本清晰并不代表送入 OCR 的画面仍清晰。后续重试等待 OCR 完成，常落入说明浮层出现之后。
- Steam 从 `20260922010124_1.jpg` 起共 6 张 1920×1080 炮口截图。中心准星 Y=540，MIL 每 50 单位约 102 像素。RNG 刻度不等距，不能把米数直接线性映射到屏幕高度。

## 实施顺序

1. 拆开截图与识别，诊断样本和 ROI 使用同一画面，PNG 保存走有界后台队列。
2. M 键在短窗口内先截取数帧，再处理已有画面；相邻两帧读数一致才锁定。开图等待过程中未回中可以继续短暂等待，按键、点击、滚轮、切窗和后续采集仍使旧操作失效。截完之后移动光标不再使已冻结的读数失效。
3. 保存代表性 ROI 与人工标注，加入真实 Tesseract 回归和可复现的 Samples 回放命令。保留跨引擎冲突即失败、严格小数格式和失败不改炮位/目标。
4. 增加独立透明穿透标尺，利用截图的 RNG/MIL 表分段插值，显示目标附近的游戏同名刻线。目标线固定在准星中心；调整游戏炮口，让同名刻线与外置刻线重合。80–684m 之外不外推。
5. 设置页提供开关、快捷键、预览距离，以及按游戏客户区分辨率保存的横向位置、中心高度、每 50 MIL 像素间距。1080p 提供实测默认；其他分辨率按高度给初值并明确可校准。FOV/缩放变化后需重新校准。
6. 完整测试、离屏设置/标尺渲染、发布到新目录并运行产物自检；留下明早验收步骤。实现不读写游戏内存、不模拟输入、不联网。

## 验收边界

自动测试验证状态、几何、真实样本识别和发布依赖。真实游戏里的热键时序、FOV、不同分辨率刻线重合与实际落点留给实机验收；截图标注和插值不等于实弹精度证明。
